# 课程计划（大致）

按目前已知的得分节点排一个大概顺序。老师后面如果改周次或交作业方式，以课堂通知为准，本文只作组内参考。

前期以**文档和范围**为主，穿插把环境跑通；后期把交易闭环、IM、AI 一并做到原型评审能演示，之后主要补安全和展示。

| 周次 | 得分环节 | 大概做什么 |
| --- | --- | --- |
| 1 | 需求构思及描述 | 写清给谁用、核心功能、安全也算需求、明确不做什么 |
| 2 | — | 把框架搭好、设计一些极度核心的接口、为之后的更新迭代做好基础 |
| 3 | 项目计划书 | 按照模版写，到时候看 |
| 4 | 立项 | ？ |
| 5 | 需求规格说明书 | 把功能写成可检查的条目，含安全 |
| 6 | 需求评审 | 开会改一版需求；之后尽量少改范围 |
| 7 | — | 开始设计草稿；登录尽量可用 |
| 8 | 软件设计规格说明书 | 架构、模块、数据、接口、安全是怎么做的 |
| 9～10 | — | 最好把大部分功能整OK |
| 11 | 原型系统评审 | 现场功能演示没问题 |
| 12～13 | — | 修漏洞、打磨体验、准备展示和渗透说明 |
| 14 | 最终展示 | 完整演示 |

以上只是大致计划，具体还是看情况。
