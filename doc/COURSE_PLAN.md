# 课程计划（大致）

按目前已知的得分节点排一个大概顺序。老师后面如果改周次或交作业方式，以课堂通知为准，本文只作组内参考。

前半学期以**文档和范围**为主，穿插把环境跑通；后半学期把交易闭环、IM、AI 一并做到原型评审能演示，之后主要补安全和展示。

| 周次 | 得分环节 | 大概做什么 |
| --- | --- | --- |
| 1 | 需求构思及描述 | 写清给谁用、核心功能、安全也算需求、明确不做什么 |
| 2 | — | 把仓库跑起来；讨论范围，避免后面大改 |
| 3 | 项目计划书 | 进度、里程碑、风险；可按老师模板写 |
| 4 | 立项 | 答辩/材料；开始准备数据库和登录 |
| 5 | 需求规格说明书 | 把功能写成可检查的条目，含安全 |
| 6 | 需求评审 | 开会改一版需求；之后尽量少改范围 |
| 7 | — | 开始设计草稿；登录尽量可用 |
| 8 | 软件设计规格说明书 | 架构、模块、数据、接口、安全怎么做 |
| 9～10 | — | 商品、下单、模拟支付、IM、AI；主路径和智能功能都能点开 |
| 11 | 原型系统评审 | 现场能演示：浏览 → 下单 → 支付，以及 IM、定价/议价；最好带一两个安全点 |
| 12～13 | — | 修漏洞、打磨体验、准备展示和渗透说明 |
| 14 | 最终展示 | 完整演示 + 按老师要求交报告 |

原型评审（第 11 周）希望已经具备：注册登录、商品、下单（价格以服务端为准）、模拟支付、IM、AI 定价与议价。  
最终展示（第 14 周）在此基础上做稳定性和攻防，按老师要求交报告。

中间没有得分的周不要空着，用来消化上一份作业、赶下一份材料或写代码。具体文档目录、答辩时长等听老师安排。
